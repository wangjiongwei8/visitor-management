# 访客管理系统（开源版）— 部署说明

> 适用对象：希望自行部署、运维本系统的人员（运维 / 管理员 / 开发者）。
> 本文档配套《操作说明书》使用。系统基于 Next.js 16 + TypeScript + Tailwind CSS + Drizzle ORM + PostgreSQL，开源协议 MIT。
> 系统零外部依赖：无需配置邮件、短信网关即可运行。

## 一、环境要求

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| Node.js | 20+ | 仅本地开发 / 构建需要；Docker 部署镜像基于 `node:20-alpine`，由镜像内提供运行时，宿主无需安装 |
| PostgreSQL | 16 | 数据库（Docker 方式已内置 `postgres:16-alpine`） |
| pnpm | 9+ | 包管理器 |
| Docker / Docker Compose | 最新稳定版 | 仅「方式一」Docker 部署需要 |
| 操作系统 | Linux / macOS / Windows | — |

## 二、方式一：Docker 一键部署（推荐）

1. 复制环境变量模板：
   ```bash
   cp .env.example .env.local
   ```
2. 编辑 `.env.local`，至少设置 `DATABASE_URL` 与 `TOKEN_SECRET`（详见第五节）。Docker 部署时 `DATABASE_URL` 通常可沿用模板默认值，但 `TOKEN_SECRET` **务必改为长随机串**。
3. 启动服务：
   ```bash
   docker compose up -d
   ```
   该命令会拉起 PostgreSQL（`visitor_db`，端口 5432）与应用（`visitor_app`，端口 4000）两个容器。应用容器启动时会**自动同步数据库表结构**并**创建默认账号**，无需手动初始化。
4. 浏览器访问 `http://localhost:4000`，使用默认账号登录（见第六节），首次登录会强制要求修改密码。

> 容器内置健康检查：应用每 30s 探测 `http://localhost:4000/api/health`，数据库就绪后应用才启动。表结构由应用启动时自动执行 `drizzle-kit push` 创建。

## 三、方式二：本地开发

```bash
pnpm install
cp .env.example .env.local      # 填写 DATABASE_URL 与 TOKEN_SECRET
pnpm db:push                    # 首次部署：将表结构同步到数据库（应用启动也会自动建表）
pnpm dev                        # 启动开发服务器，访问 http://localhost:3001
```

其他常用命令：
```bash
pnpm test        # 运行 Vitest 测试套件（27 项核心测试）
pnpm build       # 生产构建（见第八节）
pnpm start       # 以生产模式运行构建产物
```

> 本地开发需自行准备 PostgreSQL 16 实例（Node.js 20+），并在 `DATABASE_URL` 中正确指向。

## 四、部署方式对比

| 项 | Docker 部署 | 本地开发 |
|----|-------------|----------|
| 访问地址 | http://localhost:4000 | http://localhost:3001 |
| 数据库 | 容器内自动拉起 | 需自备 |
| 适用场景 | 生产 / 快速体验 | 开发调试 |
| Node 依赖 | 镜像内置（node:20-alpine） | 需本地 Node.js 20+ |

## 五、环境变量完整说明表

所有变量见仓库根目录 `.env.example`，复制为 `.env.local`（开发）或 `.env.production`（生产）后填写。

| 变量名 | 必填 | 默认值 / 示例 | 说明 | 风险 |
|--------|------|---------------|------|------|
| `DATABASE_URL` | ✅ 必填 | `postgresql://postgres:password@localhost:5432/visitor_management` | PostgreSQL 连接串，格式 `postgresql://<用户>:<密码>@<主机>:<端口>/<库名>` | 含数据库密码；生产禁止使用示例弱密码；Docker 方式默认指向容器内 `db:5432`，通常无需改动 |
| `TOKEN_SECRET` | ✅ 必填 | `replace-with-a-long-random-string-at-least-32-chars` | 登录 Token 的 HMAC-SHA256 签名密钥 | **高危**：生产必须覆盖为长随机串；若用默认值或弱密钥，Token 可被伪造导致越权登录。生成：`openssl rand -hex 32` |
| `NODE_ENV` | ✅ 必填 | `production` | 运行环境：`development` 或 `production` | 生产务必设为 `production`；`development` 会暴露错误堆栈与调试信息 |
| `DB_PASSWORD` | ⚠️ 仅 Docker | `password` | 仅 `docker compose` 初始化数据库时使用，同时写入 PostgreSQL 容器与 `DATABASE_URL` | 生产务必改为强密码；默认值极弱 |
| `DOCKER_USERNAME` | 可选 | `your-dockerhub-username` | 推送镜像到 Docker Hub 的用户名 | 无安全影响 |
| `VERSION` | 可选 | `latest` | 构建镜像的版本标签 | 无安全影响 |

> 🔒 源码中**不含**任何客户专属密钥。所有密钥仅存在于本地 `.env.local` / `.env.production`，已被 `.gitignore` 忽略，不会进入仓库。

## 六、数据库与初始化

- 数据库名：`visitor_management`。Docker 部署时由 `postgres:16-alpine` 容器自动创建。
- 审核开关：`system_settings` 表中 `review_enabled` 键，默认值为 `"true"`（即默认开启审核，安全优先）。
- 首次访问应用后完成初始化，管理员可设置密码策略、受访人清单等。

**默认账号（首次登录强制修改密码）**：

| 角色 | 用户名 | 初始密码 | 说明 |
|------|--------|----------|------|
| 管理员 | `admin` | `admin123` | 拥有全部后台权限 |
| 门卫 | `security` | `security123` | 访客签到 / 签退 |
| 员工 | `employee` | `employee123` | 被访人审核、我的预约 |
| 访客 | `visitor` | `visitor123` | 预约查询 / 演示用 |

> ⚠️ 部署到生产环境后，请立即修改以上所有默认密码。访客无需登录即可扫码预约，无需使用 `visitor` 账号。

## 七、健康检查

系统提供健康检查端点：
```
GET /api/health
```
返回 HTTP 200 表示应用与数据库连接正常。可用于负载均衡探活或容器健康检查（Docker 部署已默认启用）。

## 八、生产构建

生产构建命令：
```bash
pnpm build
```
该命令等价于 `next build --webpack`。

> ⚠️ **必须使用 webpack 构建，禁止使用 Turbopack**。`Turbopack` 与 `bcryptjs` 不兼容，使用 Turbopack 构建或运行会导致认证模块报错。Dockerfile 已内置 `pnpm run build`（`next build --webpack`）。

构建完成后以独立（standalone）模式运行，监听 `0.0.0.0:4000`。

## 九、数据备份与版本升级

### 数据备份
所有业务数据存于 PostgreSQL 的 `visitor_management` 库，通过数据卷 `postgres_data` 持久化。建议定期备份：
```bash
# Docker 方式
docker exec visitor_db pg_dump -U postgres visitor_management > backup_$(date +%F).sql

# 或本地 psql 客户端
pg_dump -h localhost -U postgres visitor_management > backup_$(date +%F).sql
```
恢复：
```bash
psql -h localhost -U postgres -d visitor_management < backup_YYYY-MM-DD.sql
```

### 版本升级
本系统保持**零数据库表结构变更**，升级主要替换应用代码 / 镜像：
1. 升级前务必先执行一次全量备份（见上）。
2. 阅读目标版本的 Release Notes，确认无新增迁移脚本。
3. Docker 方式：
   ```bash
   git pull                 # 或拉取新镜像
   docker compose pull
   docker compose up -d
   ```
   数据卷 `postgres_data` 不随容器销毁，升级不会丢失数据。
4. 本地方式：拉取新代码 → `pnpm install` → `pnpm build` → 重启服务。

> 升级后建议访问 `/api/health` 确认健康，并使用默认管理员账号登录验证关键功能。

## 十、可选：使用 Nginx 反向代理

可在应用前置 Nginx 作为反向代理（例如对外提供 80/443 访问、统一 TLS 终止）。以下为**通用示例配置**（占位域名 `example.com`、应用运行于 `127.0.0.1:4000`），仅作参考：

```nginx
# 仅作示例，使用占位域名 example.com，请勿写入真实域名 / IP
server {
    listen 80;
    server_name example.com;

    # 如需上传二维码图片等，可适当放开请求体上限
    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:4000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 若后续启用 WebSocket 实时能力，保留以下两行
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_read_timeout 60s;
    }
}
```

**Next.js 反向代理注意事项**：
- 应用以 standalone 模式运行于容器 / 进程的 `4000` 端口，`proxy_pass` 指向该地址即可。
- 若对外提供 HTTPS，请在 Nginx 配置 TLS，并将 `X-Forwarded-Proto` 设为 `https`，否则应用可能误判访问协议、生成错误的绝对链接。
- 如需在应用层（速率限制、操作日志 IP 记录）获取真实客户端 IP，请确保 `X-Forwarded-For` 已透传；应用自身的认证与逻辑不依赖代理头，安全性不受影响。
- 启用 WebSocket 时务必保留 `Upgrade` / `Connection` 头，否则连接会被中断。
- 本仓库根目录**不再包含 `nginx.conf` 实体文件**，本节约为文档内参考示例，请按需自行维护代理配置。
